# Repository Guidelines

## Project Structure & Module Organization

The React 19/TypeScript application lives in `src/`. Put feature UI in the nearest folder under `src/components/`, shared state and selector hooks in `src/stores/`, external or cross-cutting logic in `src/services/`, and browser configuration in `src/config/`. Serverless endpoints are in `api/`; the Azure App Service host is in `server/`. Source PTE content belongs in `data/source/pte/`; `data/processed/` is generated by `scripts/pte-data-pipeline.js` and should not be edited manually. Database migrations live in `supabase/migrations/`, Azure infrastructure in `infra/azure/`, unit tests beside their subjects, and Playwright specs in `tests/e2e/`.

## Build, Test, and Development Commands

Use Node 22+ and pnpm 10+.

- `pnpm install` installs locked dependencies.
- `pnpm run start` regenerates PTE data and starts Vite on port 3001; use `pnpm run dev` when generated data is current.
- `pnpm run build` type-checks the app and API, then creates the production bundle.
- `pnpm run lint` runs strict TypeScript checks; `pnpm run lint:css` checks legacy CSS.
- `pnpm test` runs all Vitest projects; `pnpm run test:e2e` runs Playwright on desktop and mobile Chromium.
- `pnpm run validate:all` validates documentation, structure, and generated datasets.

## Coding Style & Naming Conventions

Follow existing TypeScript: two-space indentation, single quotes, semicolons, trailing commas, and strict typing. Avoid `any` and broad casts. Name React components and files in PascalCase (`AudioControls.tsx`), functions and variables in camelCase, constants in `UPPER_SNAKE_CASE`, and hooks with a `use` prefix. Prefer Zustand selectors/actions and keep API calls or reusable business logic out of components. Use Radix primitives with Tailwind utilities for new UI.

## Testing Guidelines

Vitest uses `happy-dom` for `src/**/*.{test,spec}.*` and Node for `api/`, `server/`, and Azure script tests. Co-locate tests as `Thing.test.ts(x)`; reserve `tests/e2e/*.spec.ts` for user flows. Run focused checks with `pnpm exec vitest run src/config/AppConfig.test.ts` or `pnpm exec playwright test tests/e2e/tts.spec.ts`. Add regression coverage for behavior changes; no fixed percentage threshold is enforced.

## Commit & Pull Request Guidelines

Prefer Conventional Commit subjects used in recent history, such as `fix(audio): ...`, `feat(azure): ...`, and `docs: ...`. Keep each commit focused and imperative. Pull requests should explain the problem and solution, link relevant issues, list validation performed, and include screenshots or recordings for visible UI changes. Call out generated-data, migration, configuration, or deployment effects explicitly.

## Security & Configuration

Expose only `VITE_*` variables to browser code. Keep Gemini, Azure Speech, and Supabase service-role credentials server-side, and never commit `.env` files or secrets.
